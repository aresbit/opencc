# 把 CS329A 融进 opencc：哪些能进二进制，哪些进不去

目标是让 opencc 作为源码嵌进一个机器人仓库之后，能跑一个自我改进循环：
既提升自己对该仓库的操作能力，也提升仓库里的机器人代码本身。

这份文档记录分界线在哪，本轮落了什么，以及三处我没有照抄课程公式的地方。

---

## 分界线

CS329A 的内容分成性质完全不同的两类。

**进不去的：一切要动权重的。** 第 3 章的 PRM 训练、第 6 章的 GRPO / PPO / DAPO、
第 7.3.1 那个循环的第 4 步"训练"。opencc 是一个调 API 的 TypeScript CLI，
进程里没有梯度、没有优化器、没有可写的参数。把这些搬进来只能搬成注释。

**进得去的：闭式的统计量与决策规则。** 第 2 章的测试时计算分配、第 5.4 节的 UCB/UCT、
第 8.3–8.4 的 pass@k、置信区间与信用分配。这些是纯算术：没有依赖、没有 I/O、
没有模型调用。写成 TS，`bun build` 就把它们焊进 `dist/cli.js`，
在任何一个嵌入 opencc 的仓库里行为完全一致——这就是"永生为二进制信息"能兑现的部分。

**第 9.1.2 节自己给了跨过分界线的路子。** 课程在讲灾难性遗忘时提出**技能库**：
"把持续学习从参数层抬升到检索层，代价从梯度计算降为注意力计算"。
opencc 的策略 θ 本来就不是权重，而是 (系统提示 + skills + memdir + CLAUDE.md)。
于是 §7.3.1 的四步循环原样成立，只是第 4 步换了介质：

| §7.3.1 | 梯度版 | opencc 版 |
|---|---|---|
| 1 生成 | 采样 K 个候选 | `wide_research` / AgentTool 扇出 |
| 2 评估 | 奖励模型打分 | **仓库自己的验证器**（测试 / 仿真 / lint）的退出码 |
| 3 筛选 | 阈值或 top-K | 本轮落地的证据闸门 |
| 4 训练 | 加权最大似然 | 写进技能库 / memdir |

第 4 步还没做（见文末）。本轮做的是第 2、3 步——**没有它俩，第 4 步只会把噪声写进技能库**，
那正是 §7.3.3 警告的 reward hacking：阈值一松，攒下来的就不是经验而是运气。

## 为什么先做第 2、3 步：单次退出码不构成证据

opencc 的完成闸门本来就是机器核验而非模型自述——`auditCompletion()` 会 stat 文件、
跑命令、读退出码。但每一项都是**单次**的，而单次检查在验证器带随机性的仓库里问的是错问题。
机器人仓库恰恰全是这种验证器：带随机种子的物理仿真、传感器噪声下的控制器、
和定时器赛跑的测试。那里一次绿不是事实，是一次伯努利抽样。

这就是 `src/services/rsi/` 的全部动机。

### `estimators.ts` —— 这次运行到底证明了什么

- `passAtK(n, c, k)` —— §8.3.1 的无偏组合估计。用连乘 `Π (n-c-i)/(n-i)` 而不是阶乘，
  阶乘在 n 还没到有意思的量级时就溢出了。
- `wilsonInterval` —— §8.3.2。Wald 区间在 5/5 处宽度为零，等于让五次绿声称 100%；
  Wilson 解 p 的二次不等式，5/5 给出 [56.6%, 100%]，这才是五次绿该有的谦虚。
- `readEvidence` —— 把计数变成 `verified / flaky / broken / insufficient` 四档。
  `insufficient` 单列是关键：它和 `flaky` 的区别是"这东西不可靠"与"你还没看够次数"。
- `attemptsForConfidence`、`attemptsNeededForLowerBound` —— 还要跑几次。

### `trials.ts` —— 把仓库自己的验证器变成奖励信号

顺序跑 N 次，收集退出码。顺序是刻意的：碰文件系统、绑端口、驱动设备的验证器
不能对自己并发，而并发 bug 的表现形式恰好就是 flakiness——正是这里要测的东西。

失败输出会做**噪声归一化**（地址、时长、时间戳、临时路径、纯数字）后再聚类。
不归一化的话，随机验证器每次失败看起来都不一样，
"五次失败都是同一个原因"这个最有用的信号就没了。

### `allocation.ts` —— 下一份预算花在哪

§2.3 的 search / refinement 分配。

### `credit.ts` —— 哪一步在拖后腿

§8.4.1。合取型任务 Π p_t 随长度指数衰减：每步 95%、30 步只剩 21%。
取对数后可加，于是"整条链不可靠"变成"第 4 步占了 80% 的损失"。
`minAttempts` 守着这个分析自带的坑：只跑过两次、错了一次的步骤看起来是全链最差的，
其实只是没测过——报进 `underObserved` 而不是让它赢得归因，
因为错的元凶比承认缺口更糟，它会把下一轮工作派到错的地方。

### `uct.ts` —— 下一次试哪个方案

§5.4。几个候选方案摆在面前时纯贪心会锁死在第一个走运的上，
平均轮转又在已知很差的方案上浪费预算。未访问候选得分 `Infinity` 不是保护性分支，
而是规则本身：每个候选都拿到第一次机会，之后才有人拿第二次。

### `tools/SelfImproveTool` —— `rsi` 工具

五个 action：`measure` / `compare` / `allocate` / `attribute` / `select`。

渲染和算术一样重要。`insufficient` 印在 "5/5 passed" 旁边一定会被读成通过，
除非文字直说它不是：

```
INSUFFICIENT EVIDENCE — this is not a pass

Command: exit 0
Result:  5/5 passed (100.0%)
95% CI:  [56.6%, 100.0%]

5/5 passed, but 5 clean runs only establish a floor of 56.6%.
About 35 consecutive passes are needed to claim 90.0%.
```

## 三处我没照抄课程公式

**1. `ln(1/δ)/p` 换成精确解。** §2.3.5 给的样本数下界是
`N ≥ ln(1/δ)/p`，这是把 `-ln(1-p)` 近似成 `p`。p 一大就偏保守：
p=0.5、δ=0.05 时它说要 6 次，实际 5 次就够。精确解
`N = ⌈ln δ / ln(1-p)⌉` 一样只花一个对数，没有理由留着近似。

**2. search / refinement 的预算记账是不公平的。** 照 §2.3.1–2.3.2 写下来，
search 的 `C/t_s` 包含第一份初稿，refinement 的 `C/t_r` 是在 `p0` **之上**的修订轮数——
初稿白送。p=q=0.5、成本相等、预算 4 时，search 买到 4 次生成而 refinement 买到 5 次，
于是 refinement "赢"了一场它被送的比较。这里让 refinement 自付初稿费用，
除非调用方声明手上已经有一份（`draft_rate`）。

改完之后有个好性质：**当初稿和新采样同分布时，有限预算比较与渐近速率规则完全一致**——
它们本就是同一个不等式。两者分歧恰好只发生在该分歧的地方：
你手上已经有一份比新采样更好（或更差）的解，而渐近规则把这个信息丢了。

这条一致性写成了跨 288 组参数的扫描测试。写的时候抓到两个真 bug：
一是预算一大 `1 - (1-p)^N` 会因为 `1 - 1.1e-20 === 1` 而下溢成 0，
两边都变 0 于是静默平局——改成在对数空间比较；
二是 p=q、成本相等时两个对数在精确算术下相等但求和路径不同，
差一个 ulp 就会让判断在舍入噪声上翻转——加了相对容差，平局归 search。

**3. 加了课程里没有的 `compareRuns`。** §7.3.1 的筛选步需要的是"比原来好"，
不是"可靠"。这是两个闸门，混为一谈就会让循环收下只是运气好的候选。
0/5 → 5/5 是真修好了，尽管 5/5 并不能证明 90% 可靠；
4/5 → 5/5 什么都不是。用 Newcombe score 方法（两个 Wilson 区间合成差值区间），
因为它继承 Wilson 在边界上的好行为，而仓库里的前后对比恰好全在边界：改之前 0/n，改之后 n/n。

## 嵌进机器人仓库之后的两层循环

两层共用同一套证据闸门，区别只在把筛选出来的东西写到哪。

**外层——改机器人代码。** 奖励 R(τ) 是仓库自己的验证器。
`measure` 拿基线 → 改 → `compare` 判断是否真的变好 → `attribute` 定位还差哪一步。

**内层——改 opencc 对这个仓库的操作能力。** 同样的循环，但被筛选出来的是
"怎么在这个仓库里干活"的知识，写进仓库本地的技能库。

分工是清楚的：**公式进二进制，知识进仓库。** 公式在哪都一样，所以焊死；
知识是这个仓库特有的，所以留在仓库里跟着走。

## 没做的

1. **§7.3.1 第 4 步 / §7.4 Reflexion —— 把验证过的轨迹蒸馏进技能库。**
   这是真正的 RSI 闭环，也是"知识进仓库"那一半。本轮做的是它的前置：
   没有可信的筛选闸门，蒸馏只会把噪声写进技能库。
2. **`rsi` 与 GoalTool 证据闸门的对接。** `auditCompletion()` 现在还是单次跑命令；
   把它换成 `readEvidence` 之后，随机验证器下的完成判定才成立。
3. **PRM 式的过程评估。** §3.3 的蒙特卡洛步骤标注需要从每一步 rollout，
   估计量本身是确定性的，但采样成本是 agent 调用，得先想清楚预算。
4. **`compare` 自动取基线。** 现在要求调用方先 `measure` 存下计数——
   改完之后基线就取不到了，工具会明说这一点而不是猜。
